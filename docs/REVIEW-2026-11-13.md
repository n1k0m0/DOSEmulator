# Performance and correctness review, 13 November 2026

Baseline: `dbbadd9` on `main`. This review inspected the CPU decoded and REP
paths, RAM and native translation notifications, PIIX IDE bus-master DMA,
MiniGlide transport, snapshot and disk-journal code, scheduler/host clock,
network backends, updater and the offline transfer paths. The three concrete
findings below are fixed in the local worktree. This is a source and controlled
test review, not a claim that every guest workload or device is accepted.

| Area | Finding | Correction |
|---|---|---|
| CPU and memory bus | Code inspection, immediate fetch and REP MOVS source inspection requested writable RAM spans. A read could therefore publish `PhysicalRamWrite` and invalidate WHPX RAM translations. | A read-only RAM lease uses the same A20, RAM-range and mapping guards without a write notification. Actual destinations retain their writable lease and notification. |
| PIIX IDE DMA | PRD and memory-to-device source reads used the host bridge's writable physical RAM grant. | The bridge now offers a read-only PCI grant with the same MAE, bounds and PAM checks. Descriptor and source reads use it; device-to-memory DMA remains writable. |
| MiniGlide | Output-buffer preflight announced a possible RAM write before rejecting a buffer that crossed the physical RAM end. | Preflight uses a read-only physical grant. The later actual output commit still uses a writable grant. |

The first and third regressions were reproduced against the previous code with
the new tests, then passed after the corrections. The PIIX test performs an
actual memory-to-device DMA command and checks the committed payload and zero
guest-RAM write announcements. No CPU frequency, instruction clock, virtual
deadline, device completion, snapshot format or guest-visible data was changed.

## Verification

- Release solution build: zero warnings and errors.
- Common regression suite: **18,247/18,247 passed**, including the new CPU,
  REP, RAM and PIIX cases. The first private-workdir run lacked sibling GUI
  binaries and profile data; it is excluded. The final run used a complete
  isolated build and copied tracked profiles.
- WHPX MiniGlide transport: **475 controls passed**, including rejection before
  native provider execution and before any write notification.
- Native Glide batch/boundary controls passed: 2,880 whole-state comparisons,
  31 boundary controls, 19 full-state rejections and memory-epoch checks.
  These tests used controlled synthetic RAM, not a game or a visible window.
- Source quality: 1,026 code/project files, including 554 C# files and 5,985
  declarations, passed. `git diff --check` reports no whitespace errors.

An isolated Release probe with a subscribed write observer and one touched
page measured four mirrored samples of two million lease calls each. The
median was **38.65 ms** for the old writable lease used as a read and
**2.79 ms** for the new read-only lease; write announcements fell from two
million to zero, with the same checksum. This only measures that loop and its
observer. It does not establish a Windows, Doom, Glide or whole-emulator FPS
gain. The exact measurements are in the ignored private review artifact.

## Remaining limits

No new Windows 95/98, Doom II, MiniGlide game or native UI performance run was
performed. Actual impact on those workloads needs a controlled comparison on
fresh owned copies, with guest work and virtual time checked separately.
The source review found no further concrete defect in the inspected snapshot,
disk-journal, scheduler, network, updater or offline-transfer paths; that is
not a completeness or security certification. The common launcher and user
VMs were not replaced or opened, and this worktree is not committed or pushed.

## Second pass

The scheduler's deadline and cancellation paths, host clock policy, network
service and host-only queue/pipe lifecycle, PCI host permissions, MiniGlide
video batching, and transfer-path validation were inspected again. No further
reproducible product defect was established. The second pass added one
regression for the new PCI read-only grant: actual MAE disablement and all
13 PAM banks with read/write combinations must preserve admission, source
bytes and zero RAM-write notifications. The isolated Release build has zero
warnings/errors and the targeted test passes 1/1. The earlier 18,247-case
full suite predates this one additional regression; it is not relabeled as a
new 18,248-case run. No host network endpoint, native window, user VM or game
was started for this pass.

## Third pass: fixed-work CPU profile and storage boundaries

The COW append/read cache, offline import/export staging, host-only LAN pipe
lifecycle and native video batch admission were reviewed against their existing
tests. No additional reproducible correctness defect was found. A fresh
fixed-work Release CPU benchmark (seven measured samples per row, 600,000
steps per sample) measured these median host times on this machine:

| Interpreter loop | Median | Allocations per sample |
|---|---:|---:|
| near conditional branch | 15.71 ms | 0 |
| MOVZX | 19.25 ms | 0 |
| FF INC | 22.40 ms | 0 |
| x87 64-bit memory load | 31.32 ms | 17.6 MB |
| x87 64-bit memory store | 50.65 ms | 36.8 MB |

Binary stores call the exact integer/`BigInteger` quantization implementation.
These are synthetic interpreter loops, not actual game frame times or a WHPX
host-acceleration comparison. Results are retained in the ignored private
review directory.

## Fourth pass: x87 operand allocation

The measured x87 load-loop allocations came from two per-operand arrays:
physical addresses and copied input bytes. Numeric x87 memory load/store and
memory-arithmetic paths now use bounded stack spans for these transient
buffers. Shared preflight, translation, debug-data observation and device byte
access retain their order; other x87 memory operations retain their existing
array API. The same fixed-work probe reports 17.6 MB to zero allocations per
600,000 x87 64-bit load-loop steps, and 36.8 MB to 25.6 MB for the store loop.
Host timing varies across the separate runs and is not promoted as a game or
whole-emulator speedup. Exact 80-bit arithmetic itself was not changed.

The final isolated Release build has zero warnings/errors. The complete
common suite passes **18,248/18,248**, including the extra PCI regression.
Native x87 checks pass 53,248 exact rational conversion cases, 96 complete
FSTP state comparisons, 1,664 MMIO/native-register comparisons, and 32 paged
FST comparisons with their rejection controls. No protected guest image,
native window or host endpoint was used.

## Fifth pass: journal and resource lifecycle

The COW append, reopen, cache eviction and last-record recovery paths were
inspected along with host-only LAN peer retirement and offline transfer
staging. The existing COW benchmark was rerun exclusively on a newly generated
private 8,192-record journal. Nine fixed-work repetitions passed the base,
journal and exported-generation checks; median cold-open/read was 13.12 ms and
median generation export was 21.60 ms on this host. These are component
figures, not guest disk throughput. No new reproducible correctness defect or
safe performance change emerged from this pass. A private dangling-link probe
confirmed that Windows reports `ReparsePoint` to the current path guard;
there is no demonstrated bypass from that case. The previous complete
18,248-case suite and native x87 controls remain the latest full validation.
